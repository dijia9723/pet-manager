## 一、结论先行

- **MVP 一期排期：基准 10 周（先把后端 + React 后台做透，再开小程序），加外部审核 / 适配缓冲，对外承诺 14 周（约 3.5 个月）**。
- 开发顺序（已按你的要求锁定）：
  1. **W1 租户 RBAC 脚手架**（平台底座 + 三端工程骨架，本周并行发出所有外部申请）；
  2. **W2–W5 后端与后台 CRUD 为绝对主力**（档案 / 繁育 / 工单 / 触发器 / 打印 / 后台收尾，期间小程序开发不启动）；
  3. **W6–W8 抖音小程序**（Taro + React，一套语言贯通 PC 后台与 C 端）；
  4. W9–W10 联调测试、部署提审、种子商户试点；
  5. W11–W14 机动缓冲。
- 决定上线时间的不是写代码，而是**抖音企业认证 / 类目审核、挂载能力准入、打印机真机适配**这三件外部事项，它们在 W1 与编码并行启动，不占开发主线时间。
- 商业闭环逻辑成立，但"免费基础版持续获客"和"增值转化率"是最大商业不确定性，建议从现在开始谈 2\~3 家种子商户。

### 关键技术决策：多租户 Schema 路由（全项目最高优先级的技术点）

PG 连接池连接复用，直接 `SET search_path` 会在连接归还后**串租户**。定方案如下：

1. **所有租户业务数据访问强制走事务**，用 `set_config('search_path', ..., true)`（`is_local=true` 等价于 `SET LOCAL`，仅当前事务有效，COMMIT / ROLLBACK 后自动复位）：
   ```go
   // 统一入口，业务代码禁止拿裸连接访问租户库
   func TenantTx(ctx context.Context, tenantSchema string, fn func(tx *gorm.DB) error) error {
       return db.Transaction(func(tx *gorm.DB) error {
           // schema 名由系统生成（tenant_<id>），并经正则校验，无注入面
           if err := tx.Exec("SELECT set_config('search_path', ?, true)", tenantSchema).Error; err != nil {
               return err
           }
           return fn(tx)
       })
   }
   ```
   > 注意：第三参数必须是 `true`（事务级）。若写 `false`（会话级），`COMMIT` 之后连接仍停留在租户 schema 上，连接池复用时就会串租户。
   > 实现落在 `server/internal/infra/db/manager.go`，search\_path 额外带上平台 schema（如 `tenant_12, public`），以便租户事务内 JOIN 平台库的权限点字典。
2. **平台公共库**（tenant、tenant\_user）用独立连接组，永不经过租户插件。
3. JWT 携带 `tenant_id`；租户中间件把租户上下文注入 context，并对宠物 / 工单等资源 ID 做归属校验。
4. 租户开通：平台库落库后，在事务内 `CREATE SCHEMA tenant_<id>` + 用租户表 DDL 模板初始化（模板 SQL 纳入版本管理，后续按租户批量 migrate）。
5. 代码评审检查点：租户域代码中出现 `db.Model(...)` / `db.Find(...)` 等裸调用一律驳回。

### 6.2 合规与平台风险

1. **活体宠物类目**：一期严格限定"信息展示 + 咨询留资、不接线上支付"，提审突出工具属性。
2. **抖音政策变动**：挂载、团购、订阅消息规则变动频繁，外部能力全部走适配层 + 功能开关，业务代码不硬耦合。
3. **隐私合规**：手机号脱敏、临时链接绑手机号 + 时效；上线前备齐隐私政策 / 用户协议，最小化采集。
4. **摄像头内容责任**：增值包只透传不转码，商户协议明确画面合规与带宽责任归租户。

### 6.3 商业可行性

**成立的部分**

- 1688 白标热敏机裸机约 120\~220 元、PET 贴纸单张几分钱，499 套餐毛利约 50%\~65%，贴纸是天然复购品。
- "繁育台账 + 工单 + 吊牌"对猫舍犬舍是真实空白场景，差异化方向正确。
- 免费软件 + 硬件获客阻力小，增值包构成经常性收入，模型健康。

**需要验证的假设**

1. 猫舍 / 犬舍数字化付费意愿——靠种子商户访谈验证。
2. 免费用户增值转化率（行业经验个位数百分比），决定 99 元 / 月定价是否成立。
3. 一人兼顾研发、供应链、售后、地推的精力瓶颈——售后尽量产品化（安装视频、助手自动配对）。
4. 裂变激励形式与成本（返现 / 贴纸赠送 / 增值时长）需单独测算。

## 七、MVP 验收标准（Definition of Done）

1. 平台可开通租户，租户间数据隔离专项测试全部通过。
2. 租户可自助配置新业务类型并开单，工单状态、定时提醒、归档、审计全部正确。
3. 宠物档案 + 繁育台账可支撑猫舍真实配对 / 产仔 / 登记流程。
4. 锁定机型批量打印 50 张标签合格，吊牌码真机可扫（W4 达成后持续保持）。
5. C 端：扫码 → 宠物 → 商家主页 → 全店浏览 → 咨询 → 工单进度 / 影像，真机全链路走通。
6. 至少 1 家种子商户真实使用一周，留存真实工单与打印记录。
7. 数据库可备份、可恢复；增值功能（摄像头）在 UI 中完全无入口但表与开关已预留。

## 八、待决策的开放问题

1. **经营主体**：公司还是个体工商户？直接决定服务商资质申请与认证路径。
2. **打印机最终型号**：W4 真机测试后拍板，影响 499 套餐毛利与售后难度。
3. **摄像头增值包定价**：99 元 / 月不限路数 vs 单路 199 买断，阶段 2 立项前确定。
4. **咨询触达方式**：一期只做站内 + 订阅消息，是否需要短信兜底（成本与营销审核）。
5. **裂变激励形式**：返现 / 耗材赠送 / 增值时长，一期结束前出方案。
6. **Taro vs uni-app 最终取舍**：W6 门禁阶段用抖音最新基础库实测后拍板，选 React 心智一致还是端兼容性优先。
