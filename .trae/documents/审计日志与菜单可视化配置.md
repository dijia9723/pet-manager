# 审计日志中间件 + 平台侧菜单可视化配置

## Context

底座与租户 RBAC 脚手架此前核对为"全部落地"，仅剩两处预留未实现：

1. **审计日志中间件**：`middleware.OrderAudit = 900` 早已留好序位，但从未注册，无落库、无查询；
2. **平台侧菜单可视化配置**：权限点/菜单目前只能改代码（`seed.permDefs`）后重启，且 `seed` 每次启动会用代码值**覆盖**已有权限点的 `Name/Type/Scope/Path/Icon/Sort/ParentID`，即便做了页面也会被重启冲掉。

本次把两者补成可运行闭环。已与用户确认三项决策：

- 菜单可编辑与代码字典的共存方式：**seed 只补不覆盖**（已存在的 code 不再被改写）；
- 审计范围：**中间件 + 落库 + 平台查询接口 + 平台只读页面**；
- 配置页交互：**表单式 + 排序字段，不做拖拽**。

实施中还发现一个**必须先修的既有隐患**：`rbac.ResolvePermissions` 用 `tx.Raw` 裸 SQL，绕过 GORM 软删作用域，被软删的权限点（乃至角色）仍会被解析生效。若不同步修掉，配置页的"删除权限点"会形同虚设。

## 一、审计日志

### 1. 模型与表

新建 `server/internal/model/audit_log.go`：`AuditLog` → 表 `sys_audit_log`（平台库，同时容纳平台与租户事件）。

字段：`BaseModel` + `TenantID`（0 = 平台事件）/ `UserType` / `UserID` / `Username` / `Method` / `Path` / `Route` / `Status` / `ClientIP` / `UserAgent` / `LatencyMs` / `RequestID`。

索引：`(tenant_id, created_at)`、`(user_id, created_at)`。

在 `server/internal/model/models.go` 的 `PlatformModels()` 登记（不登记则 AutoMigrate 不建表）。

### 2. 中间件

新建 `server/internal/middleware/audit.go`：

- 定义依赖接口 `AuditRecorder interface { Submit(AuditEntry) }`，沿用既有先例（`PermissionResolver` / `TenantResolver` 均定义在 middleware 包、由 modules 实现、bootstrap 注入），避免 middleware 反向依赖 modules 造成循环。
- `Audit(rec AuditRecorder) gin.HandlerFunc`：方法白名单 `POST/PUT/PATCH/DELETE`；在 `c.Next()` **之后**读取 ctxkey（此时 Auth / TenantScope 已回填）；`UserType == ""` 直接跳过（登录、刷新、公开路由天然不记）。
- **刻意不记录请求体**：重置密码等接口的明文口令绝不能进审计表。追溯依赖 `route` + `status` + 操作人 + `request_id`。
- 注册到 `server/internal/bootstrap/app.go` 的 registry：`Add("audit", middleware.OrderAudit, middleware.Audit(auditSvc))`。

### 3. 模块

新建 `server/internal/modules/audit/{module.go,service.go,handler.go}`：

- `Submit`：**非阻塞**投递到带缓冲 chan（`select/default`，队列满即丢弃并计数告警），单 worker 用 `context.Background()` + 超时经 `manager.Platform()` 落库。审计失败绝不影响主请求。
- 提供 `Run(ctx)` / `Close()`；bootstrap 启动 worker，`Shutdown` 时停止并 flush。
- 查询接口：`GET /api/v1/platform/audit-logs`，权限点 `platform.audit.list`；参数 `page/page_size/tenant_id/user_id/username/method/path/status/start/end`；返回 `response.Page`。

### 4. 前端

新建 `admin/src/api/audit.ts`、`admin/src/pages/platform/audit/index.tsx`（ProTable + 筛选条件，只读，删除/编辑不提供）；在 `admin/src/router/routes.tsx` 注册，icon 沿用现有 key `safety`。

### 5. 种子

`seed.permDefs` 增加菜单 `platform.audit`（path `/platform/audit`）+ 按钮 `platform.audit.list`。

## 二、平台侧菜单可视化配置

### 1. seed 改"只补不覆盖"

`server/internal/seed/seed.go` 的 `seedPermissions`：已存在的 `code` **跳过、不改写任何字段**；缺失的仍按原逻辑创建。

判定用 `Unscoped()`：已被软删的 code 视为"管理员有意删除"，**不再复活**——否则重启会重建，且若其父节点已被删会导致启动报错。

影响面：

- 全新库：行为不变，逐条创建；
- 存量库：`permDefs` 新增的 code 仍会自动建出；
- 之后用代码改名称/路径/图标/排序**不再自动生效**，改由配置页治理（需同步更新 `doc/architecture.md` 中"权限点字典以代码为准"的描述）。

### 2. 新模块

新建 `server/internal/modules/permission/{module.go,service.go,handler.go}`：

| 方法 | 路径 | 权限点 |
| --- | --- | --- |
| GET | `/api/v1/platform/permissions/tree` | `platform.permission.list` |
| POST | `/api/v1/platform/permissions` | `platform.permission.create` |
| PUT | `/api/v1/platform/permissions/:id` | `platform.permission.update` |
| DELETE | `/api/v1/platform/permissions/:id` | `platform.permission.delete` |

校验：`code` 存活唯一、`type`/`scope` 枚举合法、父节点存在且 `scope` 一致、父节点不得为自身或自身子孙（防环）。

删除策略：**存在存活子节点直接拒绝**；仅软删 `sys_permission`，**不做跨租户同步清理**——残留在各租户 schema 的 `t_role_permission` 行无害，角色下次保存时自然丢弃。

### 3. 缓存失效

`server/internal/infra/session/store.go` 新增 `InvalidateAllPermissions`，内部复用已存在的 `cache.Client.DelByPrefix`（`server/internal/infra/cache/redis.go:64`）按 perm 前缀清理；权限点增删改后调用。（平台菜单不缓存、平台管理员走通配，无需处理。）

### 4. 必须一并修复的软删漏洞

`server/internal/modules/rbac/service.go` 的 `ResolvePermissions`（L63-L79）两处裸 SQL 补软删条件：

- owner 分支（L73）：`SELECT code FROM sys_permission WHERE scope = ? AND deleted_at IS NULL`；
- 角色分支（L75-L78）：`JOIN sys_permission p ON p.id = rp.permission_id AND p.deleted_at IS NULL`；
- 同时给 `JOIN t_role r` 补 `AND r.deleted_at IS NULL`（角色可软删，同样存在此问题）。

### 5. 前端

新建 `admin/src/api/permission.ts`、`admin/src/pages/platform/permissions/index.tsx`：

- ProTable 树形展示（dataSource 携带 `children`）；
- ModalForm 增改：父节点下拉（树选择）、排序数字字段、图标 `ProFormSelect`（候选为 `admin/src/layouts/menu.tsx` 现有 7 个 key；未命中时 `renderIcon` 已兜底 `MenuOutlined`，不动图标体系）；
- 在 `routes.tsx` 注册（icon 用 `setting`）；`admin/src/types/index.ts` 补类型。

### 6. 种子

`permDefs` 增加菜单 `platform.permission`（path `/platform/permissions`）+ `list/create/update/delete` 四个按钮。

## 风险与注意

- 第 900 序位是**全局**中间件，覆盖全部请求：必须靠"方法白名单 + `UserType` 非空"双重跳过 `/healthz` 与公开路由。
- 审计队列满必须丢弃，严禁阻塞主请求。
- `sys_audit_log` 增长快，后续需按 `created_at` 归档/分区。
- 删除权限点会让对应接口的 `Require` 失效、导致租户 403，删除确认文案须提示影响面。
- seed 只补不覆盖后"代码改名不生效"属预期，需在文档写明治理路径。
- 全局权限缓存失效走 `SCAN`，成本可控但应避免高频触发。
