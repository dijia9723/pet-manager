# 日志管理与配置管理（底座迭代）

## Context

上一轮已把「套餐」等业务痕迹从底座中剥离，底座 = 平台(平台用户/租户/权限点/审计日志) + 租户 RBAC + 三端工程骨架。
本轮按用户要求为底座补齐两块**通用能力**（不含业务参数）：

- **日志管理**：把现有独立「审计日志」重组进「日志管理」父菜单，并新增「登录日志」（登录成功/失败都采集）。
- **配置管理**：新增「参数配置」（key-value）与「字典管理」（字典类型 + 字典项）两张能力的 CRUD。

范围已与用户确认：**除日志/配置外不新增其它底座模块**（平台账号管理、系统监控等本轮不做）。

一贯约束：沿用现有模式（模块三层、一表一文件、声明式权限点、migrate 索引/清理、router 模块挂载、前端 routes/api/page 模板），**同步文档**。

## 一、后端

### 1. 模型（`server/internal/model/`，一表一文件，新增后必须在 `models.go` 登记）

| 文件 | 结构体 | 表名 | 关键字段 |
| --- | --- | --- | --- |
| `config.go` | `Config` | `sys_config` | `ConfigKey`(唯一) / `Name` / `Value`(text) / `GroupKey` / `Type` / `Remark` / `Status` |
| `dict.go` | `Dict` | `sys_dict` | `Code`(唯一) / `Name` / `Remark` / `Status` |
| `dict_item.go` | `DictItem` | `sys_dict_item` | `DictID` / `Label` / `Value` / `Sort` / `Status` / `Remark` |
| `login_log.go` | `LoginLog` | `sys_login_log` | `Username` / `UserType` / `TenantID` / `TenantCode` / `ClientIP` / `UserAgent` / `Status` / `Message` |

- 全部嵌入 `BaseModel`（`model/base.go`），复用 `model.StatusEnabled/Disabled`。
- **`GroupKey` 而非 `Group`**：`group` 是 PostgreSQL 保留字，裸 SQL / `Where` 易踩坑，直接命名为 `group_key`。
- `Value` 列用 `text`（`gorm:"type:text"`），不用 varchar。
- `Status` 为 `login_log` 沿用字符串但另立语义常量：在 `model/consts.go` 增 `LoginStatusSuccess="success"` / `LoginStatusFail="fail"`（审计日志的 status 是 HTTP 码 int，二者语义不同，不做强行统一）。
- `models.go` 的 `PlatformModels()` 追加这 4 个模型（平台公共库，租户 `search_path` 含 public，可读）。

### 2. 迁移（`server/internal/migrate/migrate.go`）

- `platformPartialUniqueIndexes` 追加（**必须带 `WHERE deleted_at IS NULL`**）：
  - `uk_sys_config_key ON sys_config (config_key)`
  - `uk_sys_dict_code ON sys_dict (code)`
  - `uk_sys_dict_item_value ON sys_dict_item (dict_id, value)`
- `platformIndexes` 追加：
  - `idx_sys_login_log_tenant_time ON sys_login_log (tenant_id, created_at DESC)`
  - `idx_sys_login_log_username_time ON sys_login_log (username, created_at DESC)`
  - `idx_sys_dict_item_dict ON sys_dict_item (dict_id)`
- `platformCleanup` 无需改动（纯新增表）。

### 3. 权限点与菜单（`server/internal/seed/seed.go` 的 `permDefs`，父必须先于子声明）

```
platform.log           菜单  日志管理   (path 空)            sort 30  icon log
  platform.audit       菜单  审计日志   /platform/audit     （已存在，见下"结构对齐"）
  platform.loginlog    菜单  登录日志   /platform/login-logs sort 32 icon log

  platform.dict        菜单  字典管理   /platform/dicts      sort 56 icon appstore
```

- **结构对齐（一次性、幂等）**：seed 新增 `alignMenuStructure`，仅在 `platform.audit` 仍为根（`parent_id = 0`）时把它挂到 `platform.log` 下。这是对「只补不覆盖」的**窄例外**：守卫条件保证管理员若已在菜单配置页调整过就不覆盖，可重复执行无副作用；需在函数上写清注释。

### 4. 新模块（`server/internal/modules/<name>/{module.go,service.go,handler.go}`）

| 模块目录 | `Name()` | 路由（`r.Platform`） | 权限点 |
| --- | --- | --- | --- |
| `config` | `platform.config` | `GET/POST /configs`、`PUT/DELETE /configs/:id` | `platform.param.*` |
| `dict` | `platform.dict` | 类型 `GET/POST /dicts`、`PUT/DELETE /dicts/:id`；项 `GET/POST /dicts/:id/items`、`PUT/DELETE /dicts/:id/items/:itemId` | `platform.dict.*` |
| `loginlog` | `platform.loginlog` | `GET /login-logs`（**只读，绝不暴露写接口**） | `platform.loginlog.list` |

- service 分层照抄 `modules/permission`（CRUD）与 `modules/audit`（只读分页）；`handler` 照抄 `pathID` + `response.OK/Fail`；分页用 `pagination.Query` + `response.NewPage`。
- `dict` 删除字典类型时**级联软删其下字典项**（同一事务）。

### 5. 登录日志采集（auth 集成）

- 在 **auth 包内定义消费方接口**（Go 惯例，auth 不 import loginlog，无循环依赖）：
  ```go
  type LoginRecorder interface { Record(ctx context.Context, r LoginRecord) }
  type LoginRecord struct {
      Username, UserType, TenantCode, ClientIP, UserAgent, Status, Message string
      TenantID uint64
  }
  ```
- `auth.Service` 增加该依赖，`NewService` 增参；`modules/loginlog` 的 Service 实现 `Record`（**普通同步写**，超时保护，失败仅 `log.Warn`，绝不影响登录响应；登录是低频操作，无需上 audit 那套队列）。
- 记录点在 `modules/auth/handler.go` 的 `handleLogin`（此处才有 `gin.Context` 可取 `ClientIP()/UserAgent()`）：
  - 成功：身份/租户取自 `result.User`，`Status=success`。
  - **失败也记**（安全价值在失败）：`Login()` 失败返回 nil 拿不到租户，按 `input.TenantCode` 是否为空推断 `UserType`，`Message` 取错误文案，`Status=fail`。
- 注：`/auth/login` 未登录，不在审计中间件（只记录登录后写操作）覆盖内，不会与登录日志重复。

### 6. 空 path 父菜单剪枝

- `modules/auth/service.go` 的 `Menus()` 返回前，递归剔除「`path == ""` 且无 children」的节点，避免父菜单在子项被过滤后退化成可点击的空叶；前端 `toMenuData` 做同样过滤。

### 7. 装配（`server/internal/bootstrap/app.go`）

- 构造 `loginlogSvc` / `configSvc` / `dictSvc`；`loginlogSvc` 需先建再传给 `auth.NewService`。
- `modules` 切片追加 `configSvc, dictSvc, loginlogSvc`。
